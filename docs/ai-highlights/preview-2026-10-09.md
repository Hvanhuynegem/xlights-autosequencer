# Validated v1 highlight previews — 2026-10-09

The v1 API now generates baseline and accepted-highlight section previews using
the same saved inputs and production runner as export. It validates live context
before reusing cached serialization or delivering a downloaded artifact. This
completes the backend preview/cache connection; UI playback and real xLights
visual acceptance remain pending.

## API

`POST /api/v1/songs/<song_id>/preview` is synchronous and returns HTTP 200 with
`preview_id`, `cached`, `status: done`, `variation_seed`, `highlights`,
`highlight_revision`, and `result` (section/index, duration, theme, placement count,
warnings and `artifact_url`). The song must be themed with an available source
and committed layout. Example after accepting a plan:

```json
{"section_index": 0, "highlights": true}
```

Optional fields:

| Field | Behavior |
|---|---|
| `section_index` | Nonnegative integer; omit/null selects a representative section from the actual completed plan |
| `highlights` | Omit to honor saved enabled state; true requires enabled accepted intent; false explicitly previews baseline and skips unreadable sidecars |
| `variation_seed` | uint32; omitted uses enabled accepted intent's seed or the baseline song default |
| `vocal_diarization` | Boolean, defaults true as in export |
| `include_extra_timing` | Boolean, defaults true as in export |

For A/B comparison, send the enhanced response's exact seed and section index
with `highlights: false`. Baseline's default seed can differ from a custom accepted
seed. Explicitly requesting a changed seed/options on an accepted plan can fail
`stale_plan`; no silent baseline fallback occurs.

GET the returned `artifact_url` to download an `.xsqz` ZIP containing `preview.xsq`,
the generation-time layout and any media copied alongside the scoped XSQ by the
writer (tested with Video). The original song audio still needs to be available
when opening in xLights, as for current exports. GET revalidates the original
request snapshot and live generation context; changed inputs return 409 instead
of delivering stale output. Responses use `Cache-Control: no-store`.

Unknown options, duplicate JSON keys, nonfinite values and wrong scalar types are
rejected. Common errors: `highlights_unavailable`, `highlight_state_unreadable`,
`stale_plan`, `stale_preview`, `generation_inputs_changed`, `invalid_section`, and
`preview_not_found` after cache eviction. No saved highlight state is changed.

## Cache and generation behavior

- New `src/review/api/v1/preview.py` uses the same `generation_inputs` as export,
  including session themes/sliders, story, lyrics/vocals, extras and preferences.
  The legacy `/api/song/<hash>/preview` is a separate brief/legacy-library route;
  it retains its contract and does not load v1 accepted state.
- `generator_runner.run` accepts an optional `SectionPreviewRequest`. All prior
  callers keep their existing return behavior; preview mode returns a typed
  `GeneratedSectionPreview`. Full baseline/context capture and accepted-plan
  compilation run under the existing runner RNG lock.
- Each POST/download reconstructs current generation context. Cache reuse skips
  scoped serialization and media copying, **not** baseline generation. Avoiding
  generation safely would require a complete dependency manifest. The runner's
  cache identity includes current context, accepted state/revision, selected
  section, lyrics/words/phonemes, timing/vocal options, metadata and filenames.
  The API additionally compares session/song/options and source/layout/story
  content before publishing. Source, layout, story and configured video are
  checked across runner generation. Arbitrary external writes are not globally
  transactional.
- Artifacts are memory-only, bounded to 16 entries and 64 MiB total payload.
  An individual larger artifact returns 413; expired URLs return 404.
  No proposal jobs, background progress or cancellation API were added.

## Scoped serialization

`write_section_preview` is shared by the production runner and legacy preview.
It copies the completed plan before writing, retains intersecting adjacent
sections when the minimum window extends beyond a short section, and preserves
all existing song-level collections. Copying prevents the writer's video-path
and layer rewrites from modifying the original full plan.

Model-effect timestamps and all timing layers, including lead/backup lyric
layers, are clipped to the preview clock. Supported highlight On ramps get
interpolated start/end brightness when cut by a boundary, preserving their
measured rise/decay segment. Other clipped animations can restart their phase;
the response reports that approximation. This is a sequence artifact, not a
browser-rendered A/B player or proof of xLights blend/visual fidelity.
