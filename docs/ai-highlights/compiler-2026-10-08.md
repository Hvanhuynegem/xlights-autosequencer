# Highlight compiler and XSQ proof — 2026-10-08

Two initial recipes now compile reviewed events into normal generator placements and serialize through the real XSQ writer. The compiler is not yet called by application export or preview, and the API still cannot accept lighting plans. This is the compiler portion of P4.1/P4.2, not completion of the manual-to-render milestone.

## Behavior

- `sustained_wash` uses two catalog-backed `On` effects: rise from zero to the selected intensity, then decay to zero at the event's end. It requires an interior measured/manual peak and accepts sweep/wash/unknown-texture events. Aligned total duration: 250–30000 ms.
- `isolated_impact` uses one `On` pulse, declining from the selected intensity to zero. It accepts impact events with 50–1000 ms treatment duration. Point events need an explicit end offset; a peak is not fabricated.
- Both inherit one section color, use additive blending, disable shimmer, and cap brightness endpoints at 100. They are nonspatial lighting accents. Spatial sweeps, background dimming, buildup/release, gap/re-entry, and fill recipes remain future work.
- Timing stays unsnapped in saved events. Compilation uses the sequence interval, rounds nearest with ties up, and caps at the last full frame inside the recording. Collapsed peaks/durations and section-boundary crossings are rejected.
- Layout groups resolve recursively to physical models. Unknown/cyclic groups, dedicated singing props, unsupported/DMX models, unsuitable catalog entries, overlapping highlights, protected content and fade masks are rejected.
- Existing same-target effects keep their layers; highlight placements get a lower, frontmost layer. Ordinary effects on *other* groups sharing those pixels currently cause `ambiguous_composition`. This intentionally limited compiler cannot guarantee visibility on a busy overlapping layout; P4.3 must resolve that compositor behavior.
- No caller's baseline or saved intent is mutated. Invalid proposals raise `HighlightCompileError` with an issue code. Explicit targets are retained; unavailable targets are never silently replaced.

[Compiler API](../../src/generator/highlights.py): `compile_highlights(baseline, plan, *, context, events, layout, effect_library)` returns a placement dictionary to attach to `SequencePlan.highlight_effects`. The caller must construct `context` from current generation inputs. Comparing a plan with its own context is **not** live validation. Accepted-plan API/export integration must supply that missing boundary before enabling replay.

`EffectPlacement.frame_interval_ms` and `SequencePlan.highlight_effects` are appended defaulted fields, preserving positional callers. Existing placements keep the original 25 ms rounding/minimum-duration behavior. The compiler passes its interval explicitly, and the XSQ header now uses `SequencePlan.frame_interval_ms`. Existing nonempty baseline placements must already match that interval and fit the recording; compilation rejects incompatible timing rather than silently retiming the baseline. Empty plans remain a no-op.
